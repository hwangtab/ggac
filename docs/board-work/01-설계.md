# 이사회 업무툴(board-work) 설계 — kosmart-work 이식

> 2026-10-29 작성. 원본은 `~/kosmart-work`(한국스마트협동조합 업무툴, Next.js +
> Supabase). 결정 사항(사용자): **원본의 채팅·DM·채널·자료실·문서
> 뷰어·편집기·검색·웹 푸시를 코드째로 가져온다 / `/board-room` 아래에 둔다 /
> 실시간은 폴링으로 한다.**

## 0. 한 줄 요약

kosmart-work의 클라이언트 코드(컴포넌트·순수 로직, 약 60%)는 **복사**하고,
Supabase에 기대던 부분 (RLS·트리거·RPC·Storage·Realtime, 약 40%)은 **ggac
방식(Turso + Drizzle + Better Auth + Vercel Blob)으로 다시 쓴다.** 원본
컴포넌트가 import하는 모듈 경계(`realtime.ts`·server action
시그니처·`ActionResult`)를 그대로 유지해서, 다시 쓰는 부분이 화면 코드에 번지지
않게 한다.

### 가져오지 않는 것 (원본 조직 전용)

- **지출결의(`expenses`)**: 한국스마트협동조합의 결재 규칙이다. 원본 코드 곳곳의
  지출결의 예외 분기는 걷어낸다.
- **위키(`wiki`)**: 원본 저장소의 `docs/`를 동기화하는 기능이다.
- **Teams 이관(`import`)·수신 웹훅(`webhooks`)·kosmart.org 역할
  동기화(`role-sync`·`subadmin-sync`)·초대(`invitations`)**: 이 툴에서는
  구성원을 ggac 이사회 권한이 정하므로 필요 없다(§3).
- **운영 경보 채널(`lib/ops`)**: 크론 실패는 ggac 로거로 보낸다.

## 2. 배치

### 2-1. URL과 라우트 그룹

URL은 그대로 두고 레이아웃만 둘로 나눈다. 기존 이사회실은 좌측 메뉴가 있는
레이아웃이고, 업무툴은 화면 전체를 쓰는 앱 셸이다.

```
src/app/[locale]/board-room/
  (classic)/                 ← 기존 페이지를 옮긴다(URL 불변)
    layout.tsx               기존 layout.tsx
    page.tsx · meetings/ · schedule/ · documents/ · assembly/ · _components/
  (work)/
    layout.tsx               requireWorkStaff() + AppShell(원본 app/(app)/layout.tsx)
    chat/ · c/[slug]/ · dm/[id]/ · inbox/ · files/ · search/ · settings/
  edit/
    [attachmentId]/ · new/   편집 화면(원본 app/edit/**, PC 전용)
```

- 기존 이사회실 메뉴에 **"업무툴"** 항목을 추가하고, 업무툴 레일에서
  "이사회실로"로 돌아가게 한다.
- `src/components/ConditionalLayout.tsx`에서
  `/board-room/(chat|c|dm|inbox|files|search|settings|edit)` 경로는 `/admin`처럼
  전역 내비게이션·푸터·`data-poster` 테마에서 뺀다. 로케일 접두사(`/en`)를 떼고
  판정한다.
- 화면 문구는 원본처럼 한국어로 고정한다. `/en/board-room/chat`에서도 한국어로
  보인다(번역은 범위 밖).

### 2-2. 코드 위치와 경로 별칭

원본 import 경로(`@/lib/auth`, `@/lib/notifications`, `@/components/ui` …)가
ggac 모듈과 겹친다. 그래서 가져온 코드는 한 디렉터리에 모으고 별칭을 따로 둔다.

```
src/work/
  lib/          원본 src/lib/* (supabase/ 제외)
  components/   원본 src/components/*
  db/           §4 스키마·쿼리(원본에 없던 층)
```

- `tsconfig.json`의 `paths`에 `"@work/*": ["./src/work/*"]`를 추가한다.
- 기계적으로 바꾼다: `@/lib/` → `@work/lib/`, `@/components/` →
  `@work/components/`(가져온 파일 안에서만).
- `tailwind.config.js`의 `content`에 `./src/work/**/*.{ts,tsx}`를 추가한다.
  빠뜨리면 클래스가 생성되지 않는다.
- Drizzle 스키마는 ggac 관례대로 `src/db/schema/work.ts`에 두고 `index.ts`에서
  재수출한다. 쿼리는 `src/db/queries/work/*`에 둔다(권한을 모르는 층 — §5).

## 3. 사람과 역할

원본은 `work.staff` 표와 초대 절차로 구성원을 관리한다. 이 툴에서는 **ggac
이사회 권한을 그대로 쓴다.** 별도 구성원 표는 두지 않는다.

| 원본 역할            | ggac에서 판정                        | 비고                                         |
| -------------------- | ------------------------------------ | -------------------------------------------- |
| owner                | `is_admin` 이고 관리자로 지정된 사람 | 원본에서 owner만 하던 일은 admin과 같이 본다 |
| admin(업무툴 관리자) | `is_admin`                           | 모든 채널 읽기·채널 관리                     |
| member               | `is_director` 또는 `is_auditor`      | 공개 채널 + 초대받은 비공개 채널             |
| guest(서브관리자)    | 1단계에서는 쓰지 않는다              | 외부 인원(회계사 등)을 들일 때 켠다          |

- 진입 조건은 `canAccessBoardRoom`(승인·활성 + 이사/감사/관리자)과 같다.
  이사에서 빠지면 다음 요청부터 바로 못 들어온다. 채널 멤버십 행은 남아 있지만
  읽을 수 없다.
- 처음 들어온 사람은 `#전체` 채널에 자동으로 넣는다(원본의 초대 수락 단계를
  대신한다).
- 이름은 `member_profiles.display_name`, 직함은 `director_title`을 쓴다. 상태
  메시지·알림 설정은 `work_member_prefs`(§4)에 둔다.
- **이메일 2단계 인증은 하지 않는다**(사용자 결정). 원본
  `email-mfa.ts`·`/mfa`·`verified_sessions`는 가져오지 않는다.

원본 Postgres `work.*` 표를 SQLite로 옮긴다. 이름은 ggac
표(`notifications`·`comments` 등)와 겹치지 않게 `work_` 접두사를 붙인다.

| 표                                                                  | 원본                           | 바뀌는 점                                                                                                      |
| ------------------------------------------------------------------- | ------------------------------ | -------------------------------------------------------------------------------------------------------------- |
| `work_member_prefs`                                                 | staff(상태 필드) + staff_prefs | 사용자 1행: 상태 이모지·문구·만료, 방해 금지, 다이제스트, 정렬                                                 |
| `work_channel_categories`                                           | channel_categories             |                                                                                                                |

| `work_reactions` · `work_mentions` · `work_bookmarks` · `work_pins` | 같음                           |                                                                                                                |
| `work_message_links`                                                | message_links                  | URL 추출은 TS(`extract_message_urls` 이식)                                                                     |
| `work_activity_reads`                                               | activity_reads                 |                                                                                                                |

| `work_pending_uploads`                                              | pending_uploads                | `draft_meta` JSON text                                                                                         |
| `work_attachments`                                                  | attachments                    | 버전 열(`previous_attachment_id`·`version_root_id`·`version_no`·`is_latest`)과 `folder_path` 포함. `blob_path` |
| `work_file_lineages`                                                | file_lineages                  | 최종본·체크아웃                                                                                                |

변환 규칙:

- `uuid` → `uuidPk()`, `timestamptz` →
  `integer timestamp_ms`(`createdAt()`/`updatedAt()`), `jsonb` →
  `text({mode:'json'})`, `bool` → `integer({mode:'boolean'})`.
- 사람을 가리키는 FK는 `member_profiles.id`로 건다. 작성자 FK는 원본처럼
  `set null`로 둔다(기록은 남긴다).
- **인덱스는 전부 스키마에 `index()`로 선언한다**(`drizzle-kit push`가 지운다 —
  CLAUDE.md).
- 마이그레이션 `0021_board_work.sql` 하나로 만든다. `_journal.json` 등록,
  `POST_CUTOVER_TABLES`, `migrationAtomicity.test.mjs`의 표·인덱스 수,
  `db:parity`를 함께 고친다(`scripts/turso/README.md` 절차).
- 전문 검색용 FTS5 가상 표는 1단계에서 만들지 않는다(§8-3).

## 5. Postgres에 있던 규칙을 어디로 옮기나

원본은 RLS·BEFORE 트리거·AFTER 트리거·RPC가 보안과 정합성을 지켰고, server
action은 그걸 믿고 썼다. ggac에는 이 장치가 하나도 없으므로 **전부 TS로 옮겨야
한다.** 빠뜨린 규칙은 에러 없이 열린다.

| 원본 장치                                                                                   | 옮길 곳                                                                 | 예                                                                 |
| ------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------- | ------------------------------------------------------------------ |
| RLS 헬퍼(`can_read_channel`·`is_channel_member`·`is_channel_owner`·`is_work_admin`)         | `src/lib/server/boardWorkAuth.ts`                                       | 모든 server action·라우트가 첫 줄에서 판정                         |
| RLS 정책(읽기 범위)                                                                         | 쿼리 함수의 **명시적 인자**(`readableChannelIds`)로 받아 WHERE에 넣는다 | 쿼리 층은 권한을 "모르지만" 범위는 받는다                          |
| harden 트리거(작성자 강제·특권 열 동결·보관 채널 쓰기 금지·`post_policy`·스레드 1단계)      | 쿼리 층 쓰기 함수                                                       | `insertMessage`는 `author_id`를 인자로만 받고 `kind`·카운터를 고정 |
| AFTER 트리거(답글 수·첨부 수·생성자 owner 등록·링크 추출·노트 개정·`is_latest` 재계산)      | 같은 `db.transaction` 안                                                | 메시지 삽입과 부모 `reply_count` 재계산을 한 트랜잭션에            |
| RPC(`my_channel_unread_counts`·`my_activity_*`·`push_recipients`·`file_lineage_versions` …) | `src/db/queries/work/*.ts`의 SQL                                        |                                                                    |
| Realtime 브로드캐스트 트리거                                                                | `rev` 증가(§6)                                                          |                                                                    |

- 원본 server action은 Postgres 에러 코드(23505·42501 …)를 한국어 메시지로
  바꾼다. SQLite 에러는 모양이 다르므로 `lib/supabase/errors.ts` 자리에 SQLite용
  판정 함수를 둔다.
- `lib/supabase/query.ts`의 `must`/`mustList`/`soft`는 같은 이름·의미로 다시
  구현한다("실패를 빈 목록으로 둔갑시키지 않는다"는 원본 규약 유지).

### 5-1. server action을 그대로 쓴다

원본 채팅은 route handler 없이 server action만 쓴다(`'use server'` 파일 약
20개). ggac에는 server action이 아직 하나도 없지만, **API 라우트로 바꾸면
클라이언트 컴포넌트 수십 개를 고쳐야 하므로 그대로 쓴다.**

- 모든 action은 첫 줄에서 `requireWorkStaff()`를 부른다. 원본 `requireStaff()`의
  반환 모양 (`{ user, staff }`)을 맞추고, `supabase` 자리는 없앤다.
- **정적 가드를 늘린다**: `scripts/testing/assert-runtime-risks.mjs`가
  `src/work/**` 아래 `'use server'` 파일의 모든 export 함수가
  `requireWorkStaff`(또는 `requireWorkAdmin`)를 부르는지 본다. 지금 가드는
  `api/board-room/**`의 `route.ts`만 본다.
- 파일 다운로드·업로드 토큰·렌더·푸시 구독·크론은 원본도 route handler다.
  `/api/board-room/work/**`에 두어 기존 가드(`requireBoardMember` 필수) 범위
  안에 들어가게 한다.
- 가드는 보조 장치다. **안전망은 E2E**(§10)다.

## 6. 실시간 → 폴링

원본은 Realtime 이벤트를 **"무엇이 바뀌었나" 신호로만** 쓰고, 화면에 그리는 값은
서버에서 다시 읽는다 (`src/lib/messages/realtime.ts`). 이 구조 덕분에
**`realtime.ts`의 내보내는 인터페이스(토픽 구독·`TopicEvent`· 상태)를 그대로
두고 내부만 폴링으로 바꾸면**, 이걸 쓰는
ChannelView·ThreadPanel·SidebarLiveUpdates· ConversationTabBar·ChatStatus는
고치지 않아도 된다.

### 6-1. 변경 커서

- `work_channels.rev`: 그 채널에서 메시지·반응·고정·탭·노트가 바뀔 때마다 1
  증가한다. 쓰기와 같은 트랜잭션에서 올린다.
- `work_messages.rev`: 메시지가 바뀐 시점의 채널 `rev` 값. 메시지
  수정·삭제·반응·답글 수 변경 때 갱신한다.
- 고정·탭·노트는 채널별 `pins_rev`·`tabs_rev`를 따로 둔다(원본도 이 둘은 별도
  재조회다).
- 사용자 단위 변화(새 채널에 초대됨·새 DM)는
  `work_member_prefs.membership_rev`로 알린다.

### 6-2. 동기화 엔드포인트

`POST /api/board-room/work/sync`

```
요청  { channels: { [channelId]: rev }, membershipRev, focus: { channelId, threadId? }, typing?: {...} }
응답  {
  changed:  { [channelId]: { rev, messageIds: [...], pinsChanged, tabsChanged } },
  membershipChanged: boolean,
  badges:   getSidebarBadges()와 같은 모양,
  typing:   [{ userId, displayName, scope }],      // focus 채널, 5초 이내
  online:   [userId]                               // 60초 이내 접속
}
```

- 클라이언트는 `messageIds`를 원본과 똑같이 `loadMessagesByIds`로 다시 읽는다.
  삭제·반응 확인 로직도 원본 그대로다.
- 응답에 `messageIds`가 너무 많으면(예: 200개 초과) `resync: true`를 보내 원본의
  `refetchLatest` 경로를 탄다.

### 6-3. 주기

| 상황                                      | 주기                                                                   |
| ----------------------------------------- | ---------------------------------------------------------------------- |
| 탭이 보이고 채널·스레드를 보는 중         | 3초                                                                    |
| 탭이 보이지만 채팅 화면이 아님(자료실 등) | 10초(배지만)                                                           |
| 탭이 숨겨짐                               | 멈춤. 다시 보이면 즉시 1회(원본의 "30초 숨김 뒤 재동기화"와 같은 자리) |
| 연속 실패                                 | 3 → 6 → 12 → 30초 백오프, `ChatStatus`에 "연결 끊김" 표시              |
| 메시지를 보낸 직후                        | 즉시 1회                                                               |

- 입력 중 표시: 입력하면 최대 3초에 한 번 `typing`을 실어 보내고, 5초 동안
  보인다. 3초 폴링이라 원본보다 1~3초 늦다.
- 접속 표시: sync 요청이 들어오면 `work_presence.last_seen_at`을 갱신한다(쓰기는
  30초에 한 번으로 줄인다).
- 레이트 리밋: 새 키 `WORK_SYNC`(분당 60)와 `WORK_WRITE`(분당 60)를
  `distributedRateLimiter.ts`에 추가한다. 기존 `POST_CREATION`(분당 5)은 채팅에
  너무 좁다.
- 부하 추정: 이사·감사 약 20명이 동시에 채널을 열어도 초당 7건 안팎이고, 대부분
  `rev` 비교로 끝난다.

## 7. 파일 (Vercel Blob 비공개 저장소)

### 7-1. 경로

```
board-work/files/<uploadId>/<asciiSafeName>                     원본·버전 파일
board-work/files/<uploadId>/<asciiSafeName>.thumb.webp           이미지 썸네일
board-work/renders/<attachmentId>-<converterVersion>.json        미리보기 캐시
board-work/renders/<attachmentId>-<ver>-L2-layout(-p<n>).{json,svg}
```

- 비공개 저장소에는 DB 백업(`backups/`)과 메일 첨부(`mailbox/`)도 있다. 그래서
  `boardDocuments.ts`처럼 **import 없는 순수 경로 검사
  함수**(`isSafeBoardWorkPath`)를 만들어, 모든 읽기·삭제가 `board-work/`
  접두사를 벗어나지 못하게 한다.
- Blob에는 이동(`move`)이 없다. 그래서 원본처럼 `pending/` → 최종 경로로 옮기지
  않는다. **처음부터 최종 키에 올리고, 승격은 DB 행만
  바꾼다**(`work_pending_uploads` → `work_attachments`).

### 7-2. 업로드

- 브라우저가 Blob으로 직접 올린다(`@vercel/blob/client`의 `upload()`). 토큰은
  `POST /api/board-room/work/uploads`(`handleUpload`)가 발급한다. 이 단계에서
  다음을 한다: 채널 멤버 확인, `work_pending_uploads` 행 생성,
  경로·`allowedContentTypes`·`maximumSizeInBytes` 고정.
- 함수 본문 4.5MB 한도는 직접 업로드라 걸리지 않는다. 50MB를 넘으면
  `multipart: true`로 올린다.
- 완료 처리는 `onUploadCompleted`에 기대지 않는다(로컬에서 호출되지 않는다).
  원본처럼 "브라우저가 완료를 알림 → 서버가 `head()`로 크기·형식 확인 →
  승격"으로 한다.
- **원본의 TUS 이어
  올리기(`tus-client.ts`·`resume-store.ts`·`upload-client.ts`)는 버린다.**
  새로고침하면 처음부터 다시 올린다.
- 상한: 메시지당 20개, 파일당 기본 500MB(`NEXT_PUBLIC_WORK_MAX_UPLOAD_MB`). 원본
  운영값 5GB는 다운로드도 함수가 스트리밍해야 하므로(§7-3) 처음에는 낮게 잡는다.
- 이미지 썸네일은 승격할 때 sharp로 만든다(원본 `image.ts` 그대로). ggac에
  sharp가 이미 있다.

### 7-3. 다운로드와 미리보기

- 원본은 서명 URL로 302 리다이렉트하지만, ggac 비공개 Blob은 **인증된 라우트가
  스트리밍**한다 (`getPrivateObject`, 이사회 서류함과 같은 방식). 요청마다
  권한을 다시 판정한다.
- 영상·음성 탐색을 위해 `Range` 요청을 전달하도록 `getPrivateObject`를 확장한다.
- PDF는 같은 출처 `<iframe>`으로 보여 준다. 그런데 ggac는 전역으로
  `X-Frame-Options: DENY`와 `frame-ancestors 'none'`을 보낸다. **파일 표시
  라우트에만** `SAMEORIGIN`·`'self'`로 덮어쓴다.
- 문서 미리보기(kordoc: HWP·HWPX·DOCX·XLSX, 직접 구현한 PPTX, 쪽 단위 SVG
  레이아웃)는 원본 `render-*.ts`를 그대로 쓰고 캐시만 Blob에 둔다.
- `next.config.js`에 다음을 추가한다:
  - `serverExternalPackages: ['kordoc']`
  - kordoc을 쓰는 모든 라우트에
    `outputFileTracingIncludes`(`cfb`·`adler-32`·`crc-32`)
  - 선택 의존성 제외(`onnxruntime-node` 약 290MB, `@hyzyla/pdfium`,
    `@huggingface` 등)
  - 원본 `next.config.ts`의 설정을 그대로 옮긴다.
- 렌더 라우트는 `maxDuration 60`. 메모리가 부족하면 `vercel.json`에 `functions`
  메모리 설정을 추가한다.

### 7-4. 기존 이사회 서류함

1~5단계 동안 기존 `/board-room/documents`·`assembly`는 손대지 않는다. 6단계에서
`#서류함` 채널의 폴더로 옮길지 정한다.

## 8. 편집기·검색·푸시

### 8-1. 오피스·HWP 앱 안 편집

- 편집기는 별도 정적 사이트(ONLYOFFICE WASM + rhwp)에서 돌고, 부모와는
  `postMessage`로 **바이트만** 주고받는다. 원본
  `OfficeEditorFrame`·`HwpEditorFrame`·`hwp-editor.ts`·`office-edit.ts`를 그대로
  쓴다.
- **편집기 사이트는 ggac 전용으로 따로 띄운다: `~/ggac-office`.**
  - 출처: kosmart-office 스냅샷(`hwangtab/kosmart-office` 브랜치 `kosmart`, 커밋
    `1b84cde`)을 복사해 브랜치 `ggac`로 갈랐다. 내용은 ranuts/document v0.0.8
    무수정 + rhwp-studio v0.8.7 무수정(`vendor/rhwp`) + 운영 파일이다.
  - 바꾼 것은 운영 파일뿐이다:
    - `vercel.json`의 `frame-ancestors`를
      `'self' https://ggac.kr https://www.ggac.kr http://localhost:3000 http://localhost:3101`로
      바꿨다(3101은 E2E).
    - 빌드 스크립트 폴더를 `kosmart/`에서 `ggac/`로 옮겼다.
    - `KOSMART.md`를 `GGAC.md`로 바꿨다.
  - 호스팅: ggac Vercel 팀에 별도 정적 프로젝트를 만들고 `*.vercel.app` 주소를
    쓴다. **ggac.kr 하위 도메인에 두지 않는다.** 그래야 ggac 로그인 쿠키가
    편집기 출처에 닿지 않는다(`vercel.app`은 공용 접미사 목록에 있다).
  - ggac 프리뷰 배포(`*.vercel.app`)는 `frame-ancestors`에 넣지 않았다.
    프리뷰에서는 편집기가 뜨지 않는다.
  - 원본 사이트(`kosmart-office.vercel.app`)와는 배포·업데이트가 서로 묶이지
    않는다.
- ggac 쪽 CSP(`src/middleware/csp.ts`와 `next.config.js`를 **함께** 고친다):
  - `frame-src`: 편집기 출처 추가
  - `worker-src 'self' blob:`: 이미 허용됨(pdf.js 썸네일)
  - `connect-src`: Blob 직접 업로드 호스트 추가
  - 부모에는 `'wasm-unsafe-eval'`이 필요 없다(WASM은 편집기 iframe 안에서 돈다).
- 저장은 원본처럼 **항상 새 버전**이다: 업로드 → (HWP) 서버
  검증(`drafts/[uploadId]/verify`, 블록·쪽 수 비교) → `saveFileVersion`(최신본
  충돌 검사, 버전 메시지 게시) → 체크아웃 해제.

  `NEXT_PUBLIC_HWP_EDITOR_ENABLED`, `NEXT_PUBLIC_HWPX_EDITOR_ENABLED`.

## 9. UI (Tailwind 3.4)

원본은 **Tailwind v4 + shadcn base-nova(`@base-ui/react`)**이고 ggac는
**Tailwind 3.4, 컴포넌트 라이브러리 없음**이다. **ggac 전체를 v4로 올리지는
않는다.** `globals.css` 2,100줄과 `data-poster` 리맵 371개가 v3 클래스명을
겨냥하고 있어 공개 사이트가 함께 흔들린다. 그 대신 가져온 코드를 v3에 맞춘다.

- **의존성 추가**:
  - `@base-ui/react`: 헤드리스라 Tailwind 버전과 무관하다.
  - `class-variance-authority`, `cmdk`, `@tailwindcss/container-queries`
  - `tailwind-merge`: **v2**(v3는 Tailwind v4용)
  - `react-markdown`: 원본은 10이고 ggac는 9다. 업무툴 쪽만 10이 필요한지
    확인한다.
- **`tailwind.config.js` 확장**(공개 사이트에 영향 없는 추가만):
  - 원본 `@theme`의 색·반경·간격 토큰을 CSS 변수 색으로
    등록한다(`background`·`foreground`·`muted`·`border`· `ring`·`sidebar-*` 등).
  - `primary`는 ggac 하늘색 팔레트와 겹친다. 기존 `primary-50..900`은 두고
    `DEFAULT: 'var(--primary)'`만 더한다.
  - `pointer-coarse:` 변형(`@media (pointer: coarse)`)과 `dark` 변형을 등록한다.
- **업무툴 전용 CSS**: `src/work/styles.css`. 원본 `globals.css`의 CSS
  변수(oklch)를 `[data-work-app]` 범위로 옮긴다. 업무툴 레이아웃에서만
  import한다. `globals.css`는 건드리지 않으므로 `posterThemeCoverage` 검사와
  무관하다.
- **기계적 변환(코드모드)**: 원본 파일을 복사한 뒤 한 번 돌리는 스크립트
  `scripts/work/tw4-to-tw3.mjs`.

  | v4                                                | v3                                 |
  | ------------------------------------------------- | ---------------------------------- |
  | `outline-hidden`                                  | `outline-none`                     |
  | `px-2!`                                           | `!px-2`                            |
  | `w-(--anchor-width)`                              | `w-[var(--anchor-width)]`          |
  | `ring-3`                                          | `ring-[3px]`                       |
  | `in-data-[slot=x]:` · `*:` 변형 · `not-aria-[…]:` | 임의 변형(`[[data-slot=x]_&]:` 등) |
  | `@lg:` 등 컨테이너 쿼리                           | `@container` 플러그인 문법         |

  대상은 약 500개 토큰이다.
  `size-*`·`data-[…]:`·`aria-*:`·`has-[…]:`·`group-data-[…]:`는 3.4에서도
  동작한다.

- **lucide-react**: 원본 ^1.18, ggac ^0.536. 아이콘 이름이 바뀐 것이 있으면
  업무툴 쪽만 별칭으로 맞춘다.
- 테마는 원본의 밝은/어두운 테마를 그대로 쓴다. 공개 사이트의 포스터 테마와는
  분리된 화면이다(§2-1).

## 10. 테스트

- **권한 E2E(안전망)**: `e2e/authz-board-work.spec.ts`를 만들고 `authz`
  프로젝트의 testMatch 정규식에 추가한다. 시드(`seed-authz-fixtures.mjs`)에 공개
  채널·비공개 채널·DM·첨부를 넣는다. **감사(auditor) 계정이 시드에 아직 없으니
  추가한다.** 최소 케이스(허용·거부를 짝으로 단언):
  - 일반 조합원: 모든 업무툴 페이지는 `/board`로 리다이렉트, 모든
    action·라우트는 403
  - 이사: 공개 채널 읽기·쓰기 가능, **초대받지 않은 비공개 채널과 남의 DM은
    메시지·첨부·검색 결과 모두 불가**
  - 관리자: 비공개 채널 읽기 가능, 남의 DM은 불가(원본 0037 규칙)
  - 첨부 다운로드·렌더·편집 저장: 읽을 수 없는 채널의 첨부 id를 직접 넣으면 403
  - 검색: 읽을 수 없는 채널의 내용이 결과와 스니펫에 나오지 않음
  - sync: 읽을 수 없는 채널 id를 넣어도 `changed`에 나오지 않음
  - 작성자가 아닌 사람의 메시지 수정, 관리자가 아닌 사람의 `post_policy` 우회,
    보관된 채널에 쓰기 → 거부
- **단위 테스트**: 원본은 Jest다(약 119개 파일). ggac는
  `node --test`(`scripts/testing/*.test.mjs`)다. 순수 로직 테스트만 옮긴다:
  timeline·mentions·sanitize-markdown·quiet-hours·paths·zip-guard·version-rules·search
  text·render-size. 가져온 `.ts`가 `node --test`에서 로드되려면 상대 import에
  `.ts` 확장자가 필요하다. 그래서 옮길 테스트의 대상 파일만 그렇게 맞춘다.
- **쿼리 테스트**: `queriesBoard.test.mjs`처럼 실제 SQLite 파일 DB로 정합성
  규칙을 검증한다. 대상: 답글 수 재계산, `is_latest`, `rev` 증가, `post_policy`,
  보관 채널 쓰기 거부, 노트 개정 200개 유지.
- **CSP**: E2E는 `NEXT_STRICT_CSP=false`로 돌아 CSP 깨짐을 못 잡는다. 편집기·PDF
  iframe·직접 업로드는 운영과 같은 CSP로 한 번 손으로 확인한다.

### 0단계 스파이크 (실패하면 설계가 바뀌는 것)

1. **비공개 Blob에 클라이언트 직접 업로드가 되는가**(`@vercel/blob` 2.8,
   `access: 'private'`, multipart). 안 되면 4MB 조각을 서버가 받아 이어 붙이는
   방식으로 바꾼다. 큰 파일이 느려진다.
2. **kordoc이 Vercel 함수에서 도는가**: 번들 크기 한도,
   `outputFileTracingIncludes`, 메모리. 실제 HWP 6쪽을 렌더해 본다.
3. **비공개 Blob 스트리밍에 Range를 전달할 수 있는가**. 안 되면 영상·음성은 탐색
   없이 처음부터 재생된다.
4. **`~/ggac-office`를 배포한 편집기 사이트가 ggac 출처(로컬 3000)에서
   iframe으로 뜨는가**: DOCX·XLSX·PPTX·HWP를 열고 → 입력하고 → 저장해 바이트가
   돌아오는지 확인한다(§8-1).

## 12. 규모와 위험

- 가져오는 원본: 채팅 쪽 약 29.7k줄(그중 원본 인증 1.8k는 버림) +
  파일·편집·검색·푸시 약 23.3k줄. **복사 위주가 약 30k, 다시 쓰는 부분이 약
  15k줄**로 본다. 특히 다시 쓰는 곳:
  - server action 내부의 DB 접근
  - 트리거·RPC를 옮긴 쿼리 층
  - `realtime.ts` 내부
  - 업로드·다운로드
- **가장 큰 위험은 권한 누락이다.** 원본은 RLS가 "깜빡해도 막아 주는" 구조였고,
  여기서는 action 하나가 `readableChannelIds`를 빠뜨리면 그대로 열린다. §10 권한
  E2E를 1단계부터 같이 쓴다.
- **두 번째 위험은 원본과 갈라지는 것이다.** 원본은 지금도 매일 바뀐다. 이식
  시점의 원본 커밋을 `docs/board-work/원본-기준.md`에 남기고, 이후 원본 수정을
  따라갈지는 건별로 정한다.
- 편집기 사이트(`~/ggac-office`)는 원본 편집기를 고치지 않은 채로 둔다.
  업데이트는 원본 태그를 새로 받고 운영 파일만 다시 얹는 방식이다(`GGAC.md`).
