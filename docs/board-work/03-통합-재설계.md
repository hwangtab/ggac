# 이사회 업무툴 통합 재설계 — ggac 화면 체계·디자인 규칙에 녹이기

> 2026-11-03 작성. 1~5단계 이식(`01-설계.md`)은 PR #59로 운영에 나갔다. 이
> 문서는 그 결과의 **화면 구조와 디자인**을 다시 짜고, 운영에서 남은 확인 작업의
> 계획을 함께 적는다.

## 0. 무엇이 문제인가

1. **화면 전환.** 이사회실 메뉴의 '업무툴'을 누르면 전역 내비·푸터·이사회실 좌측
   메뉴가 모두 사라지고, 화면 전체가 다른 앱(kosmart-work 셸)으로 바뀐다. ggac의
   한 부분이 아니라 다른 사이트로 넘어간 것처럼 보인다.
   - 원인: `ConditionalLayout`과 `board-room/layout.tsx`가 `isBoardWorkPath()`로
     업무툴 경로를 비켜 주고, `(work)/layout.tsx`가 `h-dvh` 전체 화면
     `AppShell`을 그린다(01-설계 §2-1에서 그렇게 정했다).
2. **겹치는 길찾기.** 업무툴 셸에 자체 레일(활동·채팅·채널·할 일·자료실),
   상단바(검색·⌘K·계정 메뉴·로그아웃), 모바일 하단 탭이 있다. ggac 전역 내비,
   이사회실 좌측 메뉴, 이사회실 모바일 가로 탭과 하는 일이 같다.
3. **다른 디자인 체계.** 원본의 밝은 shadcn(base-nova) 테마를 그대로 가져왔다.
   자체 토큰(oklch 청록), 둥근 모서리(10px 안팎), 그림자, 밝은/어두운 테마
   전환이 있다. ggac는 **포스터 테마 하나**다:
   - 근사 블랙 바탕(`#08080a`), 면 `#101014`·`#16161b`, 글자 흰색 92/72/55%
   - **그림자 없음, 모서리 2px**, 헤어라인(흰 15%)으로 면을 나눈다
   - 주 버튼은 흰 바탕·검은 글자, 강조는 앰버(`#fbd9a5`) 하나
   - 포커스 링은 전역 하늘색 outline(`#0ea5e9`)
   - 근거: `src/app/globals.css`의 `data-poster` 규칙과 그 머리 주석,
     `docs/superpowers/specs/2026-08-04-hero-poster-redesign-design.md`

## 1. 목표

- 업무툴은 **이사회실의 한 영역**이다. 전역 내비·이사회실 좌측 메뉴·푸터가
  그대로 있고, 업무툴 화면은 이사회실 콘텐츠 칸 안에서 열린다.
  회의·서류함·메일함 사이를 오가듯 업무툴을 오간다.
- 업무툴의 화면 문법은 이사회실의 기존 화면(특히 **메일함의 목록·상세 2단**)과
  같다.
- 색·글꼴·모서리·버튼·입력·칩·대화상자는 ggac 포스터 테마를 따른다. 밝은 테마와
  테마 전환은 없앤다.
- 기능(채팅·폴링·파일·편집기·검색·푸시)과 URL(`/board-room/chat` 등)은 바꾸지
  않는다.

## 2. 정보 구조 — 이사회실 메뉴에 녹이기

### 2-1. 좌측 메뉴 (데스크톱)

지금의 단일 '업무툴' 항목을 없애고, 이사회실 메뉴에 **'업무' 묶음**을 둔다. 묶음
제목은 회의 목록의 그룹 라벨과 같은
모양(`text-xs font-semibold uppercase tracking-wider text-gray-400`)이다.

```
대시보드
정관
이사회 회의
일정 투표
서류함
정기총회
메일함
타임뱅크 보고
── 업무 ──────────
대화            ●3    ← 채널 + DM·그룹 (안 읽은 수 합)
활동            ●2    ← 받은 알림함(멘션·답글·반응·북마크)
할 일           5     ← 내 열린 할 일 수
자료실
검색
업무 설정             ← 알림·방해 금지·상태 메시지·푸시
```

- 원본 레일의 **'채팅'과 '채널'을 '대화' 하나로 합친다.** 목록 칸 안에서 채널
  묶음과 DM 묶음을 나눠 보인다. 이사 20명 규모에서는 둘을 따로 오갈 이유가 작고,
  메뉴 항목을 줄이는 편이 이사회실 메뉴와 어울린다. (원본처럼 둘로 나누고 싶으면
  '채널'·'메시지' 두 항목으로 두면 된다 — §8 결정 1.)
- 배지 숫자는 메뉴 항목 오른쪽에 둔다. 포스터 문법상 배지는 앰버 바탕·검은
  글자의 작은 사각(2px)이다.
- **배지는 업무 화면 밖에서도 보인다.** 회의 화면을 보는 중에도 '대화 ●3'이
  갱신된다(§4-3). 지금은 업무툴 안에서만 보인다.
- 조합원용 메뉴(`MEMBER_NAV_ITEMS`)에는 업무 묶음이 없다(지금과 같다 —
  미들웨어가 막는다).

### 2-2. 모바일

- 이사회실 모바일 가로 탭에 업무 묶음 항목(대화·활동·할 일·자료실·검색)이 이어
  붙는다. 업무툴 하단 탭은 없앤다.
- 업무 화면 안에서는 **메일함과 같은 목록 → 상세 전환**이다. 대화 목록을 고르면
  목록이 접히고 대화가 칸 전체를 쓰며, 상단에 `← 목록`(lg 미만에서만)이 있다.
  스레드도 같은 칸에서 열리고 `← 대화`로 돌아간다.

### 2-3. 업무툴 셸에서 없애는 것과 옮기는 곳

| 원본 셸 요소                                   | 처리                                                                                                                                 |
| ---------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------ |

| 상단바 계정 메뉴·로그아웃                      | 없앤다 → ggac 전역 내비의 계정 메뉴. 업무툴 로그아웃 정리(편집기 purge·푸시 해지)는 전역 로그아웃에 건다(푸시 해지는 이미 걸려 있다) |

## 3. 화면 구조 — 콘텐츠 칸 안의 2~3단

이사회실 레이아웃(`container` + 좌측 208px 메뉴 + `main.flex-1`) 안에서 그린다.
콘텐츠 칸 폭은 xl(1280)에서 약 1,008px, 2xl(1536)에서 약 1,264px다.

```
┌ 전역 내비 (fixed, 64/80px) ───────────────────────────────────────────────┐
├──────────────┬────────────────────────────────────────────────────────────┤
│ 이사회실 메뉴  │ 업무 화면 (높이 = 화면 − 위쪽 크롬, 칸마다 따로 스크롤)            │
│ (208px,      │ ┌ 목록 칸 ───┬ 대화 칸 ──────────────────┬ 패널(2xl) ──────┐   │
│  sticky)     │ │ 찾기 입력   │ # 채널 이름 · 주제 · 도구    │ 스레드 / 정보     │   │
│              │ │ 채널        │ 메시지 목록(스크롤)          │ (xl 이하에서는   │   │
│ … 업무 ──    │ │ DM·그룹     │                            │  대화 칸을 덮음)  │   │
│ 대화 ●3      │ │            │ 입력창(바닥 고정)             │                 │   │
│ 활동 ●2      │ └────────────┴────────────────────────────┴─────────────────┘   │
└──────────────┴────────────────────────────────────────────────────────────┘
  푸터 (업무 화면 아래 — 메일함과 같다)
```

- **높이:** 메일함과 같은 방식으로 업무 화면을 `h-[calc(100dvh-<위쪽 크롬>)]`,
  `min-h-[480px]`로 두고 칸마다 따로 스크롤한다(`MailboxView` 주석: 푸터 때문에
  페이지 스크롤을 없앨 수 없으니 칸 안 스크롤로 세로를 확보한다). 위쪽 크롬은
  전역 내비 + 이사회실 `py` 여백이다. 실측해서 정한다(메일함은 16rem).
- **목록 칸:** `w-72`(288px) 고정. 메일함 목록 칸과 같은
  면(`bg-white border border-gray-200 rounded-lg` → 포스터에서 `#101014`·선
  15%·2px). 머리에 찾기 입력, 그 아래 섹션별 목록. 선택 행은 `bg-primary-50`(→
  흰 7%).
- **대화 칸:** 나머지 폭. 머리(채널 이름·주제·멤버 수·고정·정보), 메시지 목록,
  바닥에 입력창.
- **패널:** 2xl 이상에서는 세 번째 칸(`w-[360px]`). 그보다 좁으면 대화 칸 위를
  덮는 오른쪽 패널이다. 화면 전체를 덮지 않는다 — 이사회실 메뉴와 전역 내비는
  보인다.
- **섹션별 목록 칸 내용:** 대화 = 채널·DM 목록 / 활동 = 알림 종류 필터 / 할 일 =
  보기(내 것·전체·완료)와 채널 필터 / 자료실 = 폴더 나무·형식 필터 / 검색 = 결과
  종류 필터 / 업무 설정 = 없음(1단).
- **편집기 화면(`/board-room/edit/*`):** 문서 편집은 폭이 가장 필요하다.
  이사회실 레이아웃 안에서 열되 콘텐츠 칸 전체를 편집기에 준다. 이사회실 메뉴를
  접는 **'넓게 보기'** 토글(기본 접힘)을 두고, 전역 내비는 유지한다. 원본처럼 PC
  전용이다(§8 결정 2).

## 4. 구현 구조

### 4-1. 레이아웃 분기 걷어내기

- `ConditionalLayout`: 업무툴 경로 예외를 지운다. 업무 화면도 전역
  내비·푸터·`data-poster` 안에서 그린다.
- `board-room/layout.tsx`: 업무툴 경로에서 `children`만 돌려주던 분기를 지운다.
  대신 업무 경로에서는 콘텐츠 칸의 `max-w`를 풀어 전폭을
  쓴다(메일함·타임뱅크처럼).
- `isBoardWorkPath()`는 남긴다. 쓰는 곳이 "메뉴를 숨길지"에서 "업무 묶음의 활성
  표시·폭 정책"으로 바뀐다.
- `(work)/layout.tsx`: `h-dvh` 전체 화면 루트와 `AppShell`을 걷어낸다. 남는 일은
  가드(`requireWorkStaff`), `#전체` 자동 가입, 사이드바 데이터 로드,
  `WorkShell`(아래)로 감싸기다. `force-dynamic`은 그대로다.

### 4-2. `WorkShell` — 원본 `AppShell`을 쪼갠 것

원본 `AppShell`(673줄)은 레일·상단바·목록 칸·우측 패널·하단 탭·빠른
이동·온보딩을 한 몸에 들고 있다. 그중 **목록 칸·대화 칸·패널의 3단 배치, 빠른
이동(⌘K), 우측 패널 문맥(`shell-context`)**만 남겨 `WorkShell`로 옮긴다.
레일·상단바·하단 탭·테마 전환 코드는 지운다. 원본
컴포넌트(ChannelView·ThreadPanel·MessageItem …)의 props와 server action은 바꾸지
않는다.

### 4-3. 배지와 폴러를 이사회실 레이아웃으로 올리기

- 지금 폴러(`realtime.ts`의 탭당 하나)는 업무 화면이 열렸을 때만 돈다. 배지를
  이사회실 메뉴에 보이려면 폴러가 **이사회실 레이아웃**에서 돌아야 한다.
- 이사회실 레이아웃(클라이언트)에 `BoardWorkBadgesProvider`를 두고,
  이사·감사·관리자일 때만 켠다(조합원은 sync가 403이라 아예 부르지 않는다). 업무
  화면 밖에서는 원본의 "배지만" 주기(10초)로, 업무 화면에서는 3초로 돈다. 탭이
  숨겨지면 멈추는 규칙은 그대로다(02-sync.md).
- 메뉴 항목의 배지와 업무 화면 안의 목록 배지가 **같은 스냅숏**을
  본다(`subscribeBadges`).

### 4-4. 디자인 토큰 바꾸기 — 한 곳에서 대부분을

업무툴 컴포넌트는 `bg-background`·`text-muted-foreground`·`bg-primary` 같은
**토큰 클래스**를 쓴다. 이 클래스는 포스터의 속성 셀렉터 재매핑에 걸리지 않는다.
그래서 `data-poster` 안에 넣는 것만으로는 색이 바뀌지 않는다.
**`src/work/styles.css`의 토큰 값을 포스터 값으로 바꾸는 것**이 가장 적게 고치고
가장 넓게 바뀐다.

| 토큰                                                                         | 지금(원본 라이트) | 바꿀 값(포스터)                                               |
| ---------------------------------------------------------------------------- | ----------------- | ------------------------------------------------------------- |
| `--background`                                                               | 흰색              | `#16161b`(이사회실 바탕과 같게)                               |
| `--card` · `--sidebar`                                                       | 흰색              | `#101014`                                                     |
| `--popover` · `--muted` · `--secondary`                                      | 밝은 회색         | `#16161b`                                                     |
| `--foreground`                                                               | 짙은 남색         | `rgba(255,255,255,.92)`                                       |
| `--muted-foreground`                                                         | 회색              | `rgba(255,255,255,.55)`(보조 본문은 `.72`)                    |
| `--border` · `--input` · `--sidebar-border`                                  | 연회색            | `rgba(255,255,255,.15)`(강조선 `.3`)                          |
| `--primary` / `--primary-foreground`                                         | 청록 / 흰색       | `#ffffff` / `#000000`(hover `primary/85`)                     |
| `--accent`(hover 면)                                                         | 연청록            | `rgba(255,255,255,.12)`(선택 `.07`, 강한 hover `.18`)         |
| `--mention` · `--mention-solid` · `--highlight`(멘션·안 읽음 배지·검색 일치) | 빨강 / 노랑       | 앰버 `#fbd9a5`, 그 위 글자 `#000`                             |
| `--unread`(굵은 안 읽음 글자)                                                | 짙은 남색         | `rgba(255,255,255,.92)`                                       |
| `--destructive`                                                              | 빨강              | `#fca5a5`(hover `#fecaca`)                                    |
| `--online`                                                                   | 초록              | `#86efac`                                                     |
| `--ring`                                                                     | 청록              | 쓰지 않는다 — 전역 `:focus-visible` outline(`#0ea5e9`)로 통일 |
| `--radius`                                                                   | 0.625rem          | `2px`(아바타·스피너만 `rounded-full`)                         |

- **밝은 블록·OS 다크 블록·수동 다크 블록을 하나로 합친다**(다크 하나).
  `darkMode` 변형과 `ThemeToggle`, `data-work-theme`를 걷어낸다. `dark:`
  클래스는 남아도 해가 없지만 코드모드로 정리한다.
- **그림자 없애기:** 업무툴의 `shadow*`는 포스터
  규칙(`[data-poster] .shadow-*`)이 이미 끈다 — 업무 화면이 `data-poster` 안으로
  들어오면 자동이다. 팝업·대화상자는 그림자 대신
  `1px solid rgba(255,255,255,.15)`.
- **모서리:** `rounded-w-*`가 `--radius` 배수라 `--radius: 2px`로 거의 끝난다.
  포스터 규칙도 `rounded-*`를 2px로 만든다.
- **업무툴 전역 outline 끄기를 지운다.** 지금 `styles.css`가 ggac의 하늘색
  포커스 outline을 업무툴 안에서 끄고 `focus-visible:ring`을 쓴다. 이걸 지워
  사이트 전체와 같은 포커스가 보이게 한다. 컴포넌트의 `focus-visible:ring-*`
  클래스는 코드모드로 걷어낸다(겹쳐 그려지지 않게).
- 포털(대화상자·메뉴)용 `body:has([data-work-app])` 범위도 같은 값으로
  바꾼다(3단계에서 고친 구조 유지).

있으면 지운다.

## 7. 위험

- **원본과 멀어진다.** R1·R3은 원본 셸과 UI 키트를 크게 고친다.
  원본(kosmart-work) 수정을 따라가기가 어려워진다. `ported.json`의 손댄 표시로
  범위를 관리한다.
- **화면 폭.** xl(1280)에서 콘텐츠 칸이 약 1,008px라, 목록 칸 288px를 빼면 대화
  칸이 약 700px다. 슬랙형 메시지에는 충분하지만 스레드는 세 번째 칸이 아니라
  덮는 패널이 된다(2xl부터 세 칸).
- **편집기.** 이사회실 메뉴 208px만큼 편집 폭이 준다 — '넓게 보기' 토글로
  메운다.
- **포스터 규칙과의 충돌.** 업무 화면이 `data-poster` 안에 들어오면 업무툴
  컴포넌트의 원시 색 클래스(남아 있다면)가 포스터 리맵을 받는다. 대부분 맞는
  방향이지만, `bg-primary-*`(흰 면 + 검은 글자 강제) 같은 강한 규칙이 예상 밖
  자리에 걸릴 수 있다 — R3 스크린숏 검토에서 잡는다.
