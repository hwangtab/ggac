# 좋아요 기능 2씩 증가 문제 해결 보고서

## 🔍 **문제 분석**

게시물에서 좋아요 버튼을 클릭할 때 좋아요 수가 1씩이 아닌 2씩 증가하는 문제가 발생했습니다.

## 🔧 **적용된 수정사항**

### 1. **중복 API 엔드포인트 제거** (우선순위: HIGH)
- **문제**: `/api/posts/[id]/like`와 `/api/posts/[id]/likes` 두 개의 엔드포인트가 동일한 기능 제공
- **해결**: 
  - 사용되지 않는 `/like` (단수형) 엔드포인트 완전 제거
  - `vercel.json`에서 `like|likes` → `likes`로 수정하여 단일 엔드포인트만 허용
  - 모든 클라이언트 코드는 이미 `/likes` (복수형) 사용 중이었음

### 2. **React StrictMode 중복 호출 방지** (우선순위: MEDIUM)
- **문제**: 개발 모드에서 React StrictMode가 컴포넌트를 두 번 렌더링하여 API 호출 중복 발생 가능
- **해결**:
  - API 레벨에서 메모리 기반 중복 요청 방지 캐시 구현
  - 1초 내 동일한 사용자+게시글+액션 조합의 중복 요청 차단
  - 캐시된 결과 반환으로 불필요한 데이터베이스 호출 방지

### 3. **클라이언트 사이드 중복 클릭 방지 강화** (우선순위: LOW)
- **문제**: 빠른 연속 클릭 시 중복 요청 발생 가능성
- **해결**:
  - `PostLikeButton` 컴포넌트에서 `isAnimating` 상태 추가
  - 로딩 중, 애니메이션 중, 권한 없음 상태에서 버튼 비활성화
  - `handleClick` 함수에서 중복 실행 방지 로직 강화

### 4. **추가 안전장치 구현**
- **서버 사이드**: 중복 요청 캐싱 및 자동 정리 (5분 후 캐시 삭제)
- **클라이언트 사이드**: 애니메이션 기간 동안 추가 클릭 차단
- **데이터베이스**: 기존 UNIQUE 제약조건으로 중복 좋아요 방지 유지

## 📊 **수정 전후 비교**

### 수정 전:
```
좋아요 클릭 → API 호출 2회 → DB 증가 2회 → 카운트 +2
```

### 수정 후:
```
좋아요 클릭 → API 호출 1회 (중복 차단) → DB 증가 1회 → 카운트 +1
```

3. 좋아요 수가 1씩 증가하는지 확인
