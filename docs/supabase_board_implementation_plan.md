### **조합원 전용 게시판 구현 계획**

---

#### **1단계: 프로젝트 환경 설정 및 Supabase 연동**

가장 먼저, 우리 Next.js 프로젝트가 Supabase와 통신할 수 있도록 기본 환경을 설정해야 합니다.

*   **작업 내용:**
    1.  **Supabase 클라이언트 라이브러리 설치:** 웹사이트 코드에서 Supabase 기능을 사용하려면 관련 라이브러리를 설치해야 합니다.
    2.  **환경 변수 설정:** 제공해주신 Supabase API 키와 프로젝트 URL을 안전하게 보관하고 코드에서 불러올 수 있도록 설정합니다. `.env.local` 파일에 이 정보들을 저장할 것입니다. 이는 민감한 정보를 코드에 직접 노출하지 않기 위한 중요한 보안 조치입니다.
    3.  **Supabase 클라이언트 생성:** 설치한 라이브러리와 환경 변수를 이용해, 프로젝트 전역에서 사용할 수 있는 Supabase 클라이언트 인스턴스를 생성합니다. 이 클라이언트는 앞으로 데이터베이스 조회, 인증 등 모든 Supabase 관련 작업을 처리하는 역할을 합니다.

*   **사용할 도구:**
    *   `run_shell_command`: `npm`을 사용하여 `@supabase/supabase-js` 와 `@supabase/auth-helpers-nextjs` 라이브러리를 설치합니다.
    *   `write_file`: `.env.local` 파일을 생성하고, Supabase 접속 정보를 기록합니다. 또한, `src/lib/supabaseClient.ts` 같은 파일을 만들어 클라이언트 인스턴스를 설정합니다.

---

#### **2단계: 데이터베이스 테이블 및 정책(규칙) 설계**

게시판의 데이터를 저장할 공간을 Supabase 데이터베이스 안에 설계합니다. 단순히 테이블만 만드는 것이 아니라, 누가 데이터를 읽고 쓸 수 있는지에 대한 중요한 보안 규칙(Policy)도 함께 정의합니다.

*   **작업 내용:**
    1.  **`profiles` 테이블 생성:** 사용자의 추가 정보를 저장할 테이블입니다. Supabase의 기본 `auth.users` 테이블과 1:1로 연결되며, 여기에 `is_member` (boolean 타입) 컬럼을 추가하여 조합원 여부를 구분합니다.
    2.  **`posts` 테이블 생성:** 게시글 정보를 저장할 테이블입니다. `title`(제목), `content`(내용), `author_id`(작성자 ID) 등의 컬럼을 포함합니다.
    3.  **RLS (Row Level Security) 정책 설정:** Supabase의 가장 강력한 보안 기능입니다. 다음과 같은 규칙을 SQL로 작성하여 적용할 것입니다.
        *   **로그인한 사용자만** 모든 게시글을 읽을 수 있다.
        *   `profiles` 테이블의 `is_member`가 `true`인 **조합원만** 새로운 게시글을 작성(`insert`)할 수 있다.
        *   사용자는 **자신이 작성한 게시글만** 수정하거나 삭제할 수 있다.

*   **사용할 도구:**
    *   `apply_migration`: 제가 작성한 SQL 쿼리를 Supabase 프로젝트에 적용하여 위 테이블과 RLS 정책을 안전하게 생성합니다. 이 도구를 사용하면 모든 변경 사항이 기록으로 남습니다.

---

#### **3단계: 사용자 인증 UI 및 로직 구현**

사용자가 웹사이트에서 회원가입하고 로그인할 수 있는 기능을 만듭니다.

*   **작업 내용:**
    1.  **인증 페이지 생성:** `src/app/login`, `src/app/signup` 과 같은 경로에 로그인 및 회원가입을 위한 UI 컴포넌트(React)를 만듭니다.
    2.  **인증 로직 연동:** 1단계에서 만든 Supabase 클라이언트를 사용하여, 사용자가 폼에 입력한 정보로 `supabase.auth.signUp()`, `supabase.auth.signInWithPassword()` 같은 함수를 호출하여 실제 회원가입과 로그인이 이루어지게 합니다.
    3.  **로그아웃 기능:** 사용자가 로그아웃할 수 있는 버튼과 `supabase.auth.signOut()` 함수를 연동합니다.

*   **사용할 도구:**
    *   `write_file` 또는 `replace`: 새로운 `page.tsx` 파일과 컴포넌트 파일을 생성하여 인증 관련 UI와 로직 코드를 작성합니다.

---

#### **4단계: 게시판 UI 및 기능 구현**

실제 게시판의 화면을 만들고, 데이터베이스와 연동하여 글을 보여주고 쓰는 기능을 완성합니다.

*   **작업 내용:**
    1.  **게시판 페이지 생성:** `src/app/board` 경로에 게시글 목록을 보여주는 페이지를 만듭니다.
    2.  **글 목록 조회:** Supabase 클라이언트로 `posts` 테이블의 데이터를 모두 가져와 화면에 렌더링합니다.
    3.  **글 작성 폼 생성:** 조합원에게만 보이는 글 작성 버튼과 폼을 만듭니다.
    4.  **글 작성 로직 구현:** 사용자가 폼을 제출하면, Supabase 클라이언트를 통해 `posts` 테이블에 데이터를 `insert` 합니다. 2단계에서 설정한 RLS 정책 덕분에, 조합원이 아닌 사용자의 요청은 데이터베이스 수준에서 자동으로 차단됩니다.

*   **사용할 도구:**
    *   `write_file` 또는 `replace`: 게시판 페이지(`page.tsx`)와 관련 컴포넌트(예: `PostList.tsx`, `CreatePostForm.tsx`) 파일을 생성하고 코드를 작성합니다.

---

#### **5단계: 조합원 관리 방안**

마지막으로, 가입한 사용자를 어떻게 '조합원'으로 승인할지에 대한 방안입니다.

*   **작업 내용:**
    *   초기 단계에서는 관리자가 직접 **Supabase 대시보드**에 접속하여, `profiles` 테이블에서 특정 사용자의 `is_member` 값을 `false`에서 `true`로 변경하는 수동 방식을 사용할 것입니다.
    *   이는 가장 빠르고 간단하게 조합원 승인 기능을 구현하는 방법입니다. 추후에 필요하다면 별도의 관리자 페이지를 구축할 수도 있습니다.
