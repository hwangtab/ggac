# WYSIWYG 편집기(Quill) 코드 리뷰 및 개선 제안

## 1. 개요

본 문서는 현재 웹사이트 게시판에서 사용 중인 WYSIWYG 편집기(`react-quill-new`)의
구현 상태를 검토하고, 잠재적인 문제점을 진단하며, 개선 방안을 제안하는 것을
목표로 합니다.

현재 편집기는 `src/components/QuillEditor.tsx` 컴포넌트를 중심으로 구현되어
있으며, 동적 로딩, 커스텀 이미지 업로드, 드래그 앤 드롭 등 고급 기능을 포함하고
있습니다.

## 2. 분석 결과 및 제안

### 2.1. 보안: 저장형 XSS (Stored XSS) - 현재는 안전

**진단:**

- **위험**: 편집기에서 작성된 원본 HTML(`post.content`)이 데이터베이스에 직접
  저장되고 있습니다 (`src/app/board/[id]/edit/page.tsx`). 만약 이 콘텐츠가
  렌더링 시점에 적절히 처리되지 않는다면, 악의적인 스크립트가 포함된 게시물을
  통해 사용자의 세션을 탈취하는 등의 심각한 XSS 공격에 노출될 수 있습니다.
- **확인**: 콘텐츠가 사용자에게 표시되는 `src/app/board/[id]/page.tsx` ->
  `PostDetailClient.tsx` -> `PostContentRenderer.tsx`의 흐름을 분석한 결과,
  `PostContentRenderer` 컴포넌트 내에서 `DOMPurify.sanitize()`를 사용하여 HTML
  콘텐츠를 안전하게 소독(Sanitize)한 후 `dangerouslySetInnerHTML`로 렌더링하는
  것을 확인했습니다.

**결론:**

- 현재 구현은 **안전**합니다. `DOMPurify`를 통해 XSS 공격을 효과적으로 방어하고
  있습니다. 허용된 태그와 속성을 명확히 정의한 설정은 좋은 보안 관행입니다.

---

### 2.2. 스타일링: CSS 충돌 및 비일관성

**진단:**

- **문제**: 편집기 콘텐츠의 스타일링에 두 가지 주요 소스가 충돌하고 있습니다.
  1.  **Quill 자체 스타일**: `QuillEditor.tsx`에서
      `import 'quill/dist/quill.snow.css'`를 통해 Quill 편집기의 기본 스타일이
      적용됩니다.
  2.  **Tailwind Typography**: `PostContentRenderer.tsx`와 `QuillEditor.tsx`에서
      `prose` 클래스를 사용하여 Tailwind의 타이포그래피 플러그인 스타일을
      적용하고 있습니다.
- **영향**: 이 두 스타일 시스템은 `h1`, `p`, `ul`, `blockquote` 등 동일한 요소에
  대해 서로 다른 스타일(마진, 패딩, 글꼴 크기 등)을 적용하려고 시도합니다. 이로
  인해 다음과 같은 문제가 발생합니다.
  - **비일관성**: 편집기에서 보는 화면과 실제 게시물에서 보는 화면의 스타일이
    미세하게 다를 수 있습니다.
  - **유지보수 어려움**: 스타일을 수정하려면 양쪽 시스템을 모두 고려해야 하므로
    복잡성이 증가하고 예측이 어렵습니다.

**개선 제안:**

- **단일 진실 공급원(Single Source of Truth) 확립**: 스타일 충돌을 근본적으로
  해결하기 위해, 편집기 콘텐츠 전용의 독립적인 CSS 스타일시트를 만드는 것을
  권장합니다.
  1.  **`editor-content.css` 파일 생성**: `src/styles`와 같은 공용 디렉토리에
      CSS 파일을 생성합니다.
  2.  **스타일 정의**: 이 파일 내에서 `.ql-editor` 클래스를 루트로 사용하여
      편집기 내부 요소(예: `.ql-editor h1`, `.ql-editor p`)에 대한 스타일을
      명확하게 정의합니다. 이 스타일은 최종 렌더링될 `prose` 스타일과 시각적으로
      동일해야 합니다.
  3.  **전역 적용**: 생성한 CSS 파일을 `layout.tsx` 등에서 전역으로
      임포트합니다.
  4.  **`prose` 클래스 제거**: `PostContentRenderer.tsx`와 `QuillEditor.tsx`의
      `className`에서 `prose`를 제거합니다.

- **기대 효과**:
  - 편집기와 실제 게시물 간의 스타일이 100% 일관성을 유지합니다.
  - 스타일 관련 유지보수가 단일 파일(`editor-content.css`)로 중앙화되어
    단순해집니다.

### 2.3. 코드 구현: 이미지 업로드 로직의 복잡성

**진단:**

- **문제**: `QuillEditor.tsx` 내의 이미지 업로드 및 삽입
  로직(`handleImageUpload`, `insertImageToEditor`)이 `setTimeout`과 여러 단계의
  콜백을 사용하여 구현되어 있어 복잡하고 잠재적으로 불안정합니다.
- **영향**:
  - **취약성**: `setTimeout`에 의존하는 로직은 특정 조건(예: 느린 네트워크,
    예기치 않은 Quill API 동작)에서 실패하거나 레이스 컨디션(Race Condition)을
    유발할 수 있습니다.
  - **가독성 저하**: 코드가 여러 함수에 걸쳐 비동기적으로 얽혀 있어 흐름을
    파악하고 디버깅하기 어렵습니다.

**개선 제안:**

- **로직 리팩토링**:
  1.  **Promise 기반 단순화**: `async/await`를 적극적으로 사용하여 이미지
      업로드, URL 반환, 에디터 삽입 과정을 명확한 선형 흐름으로 재구성합니다.
      `setTimeout` 의존성을 제거하거나 최소화해야 합니다.
  2.  **Quill API 재검토**: `react-quill-new` 또는 Quill 자체의 최신 문서나
      예제를 참고하여 이미지 삽입을 위한 더 안정적이거나 현대적인 API가 있는지
      확인하고 적용하는 것을 고려합니다.

- **기대 효과**:
  - 코드의 안정성과 예측 가능성이 향상됩니다.
  - 로직이 단순화되어 향후 유지보수가 용이해집니다.

## 3. 요약 및 실행 항목

1.  **[필수] CSS 충돌 해결**: `editor-content.css`를 생성하여 편집기 콘텐츠
    스타일을 중앙화하고, 기존 `prose` 클래스 적용을 제거하여 스타일 비일관성
    문제를 해결합니다.
2.  **[권장] 이미지 업로드 로직 개선**: `QuillEditor.tsx`의 이미지 업로드 관련
    함수를 `async/await`를 사용하여 보다 안정적이고 읽기 쉬운 코드로
    리팩토링합니다.
